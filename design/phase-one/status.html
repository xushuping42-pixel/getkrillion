This selector demonstrates interface states. It does not run a request, simulate a successful capture, or change the real status above.

Two checks. One game-date key.

The proposed recording windows are 12:20 and 13:20 Beijing time (04:20 and 05:20 UTC). Every run computes its own America/New_York date. A valid record for that exact date skips another request. A successful previous-day capture must never suppress the new day’s later run.

A failure keeps the previous date visible.

Wrong dates, incomplete prompts, inconsistent scores and conflicting duplicates stop publication. Permission errors are recorded rather than retried in a tight loop. The previous complete edition remains clearly dated.

Notifications still need a real destination.

External alerts are not configured. A failed run can report the target date and failed stage locally, but this preview does not claim that an email or WeChat message has been delivered.
