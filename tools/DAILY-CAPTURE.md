# Hourly official reveal capture

- Workflow: .github/workflows/record-answers.yml, every hour at minute 17; the script uses America/New_York rather than a fixed daily UTC offset. Existing complete records exit without another API request.
- Canonical archive remains design/phase-one/records/YYYY-MM-DD.json. Only HTTP 200, date-matched, seven-prompt records with nonempty answers, scores, unique answer names and acceptable total size enter it. Schema/tier validation is stricter than the minimum numeric-score check.
- The comparison baseline is the closest earlier valid edition. A change outside 0.1–1.9 times its answer count fails. With no earlier edition, the first validated capture establishes the baseline. --force does not bypass any gate.
- Backfill: node tools/fetch.mjs --date=2026-11-19 --force. It never moves the latest pointer backwards. Dispatch inputs support the same date and force flag.
- Status: /status/ is noindex, excluded from the sitemap, shows 14 Eastern dates with validated presence and fetchedAt in ET and UTC, and is regenerated on every hourly run even after capture failure. It reflects the last build, not live browser polling.
- Required GitHub Secrets for Resend: RESEND_API_KEY, ALERT_EMAIL_FROM (verified sender), ALERT_EMAIL_TO (one address or comma-separated list). Do not commit values. A configured API accepting a mail is not proof of inbox delivery; verify the real recipient/mail provider logs.
- Alerts: first hourly run on/after 02:00, 06:00 and 12:00 ET while today's record is missing. Each date/level is sent once, with catch-up for missed thresholds. Noon logs at most the first 500 response characters. Pending stable payloads, provider message IDs and sent timestamps persist in design/phase-one/alert-state.json; failed sends are retryable and use a provider idempotency key. Never delete this state just to retry a job.
- Failure diagnostics include ET date, UTC time, HTTP status (or no response), prompt count, each answer count, last successful date and failing validation stage. Missing email configuration fails explicitly, never reports a successful send.
- Validation: node --test tests/design-recording.test.mjs tests/hourly-capture.test.mjs, then node tools/build-guide.mjs and node --test. The seven-day test uses synthetic dates; it does not establish seven days of production operation.
- GitHub schedules are best effort and can be delayed or disabled after inactivity. An independent scheduler/heartbeat is needed for a strict two-hour delivery SLA and for detecting a workflow that never starts. Check default-branch workflow activation, Secrets, run history and real email delivery before starting the live seven-day acceptance period.
